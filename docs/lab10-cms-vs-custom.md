# Лаба №10: CMS (Directus) против собственной разработки

## Что сделано

Directus — headless CMS, поэтому «сайт на CMS» здесь — это **панель модерации
Sagas** (http://localhost:8055). Публичный сайт по-прежнему рисует наш React.

### 1. Тема (только настройки)
- Плагин-тема `@directus-labs/dark-terminal-theme` — тёмный «ретро-терминал»,
  в стиле сайта («dark hacker-terminal aesthetic» со страницы About).
- Название, подзаголовок «Moderation», фирменный зелёный `#0EA64E`, логотип-молния,
  текст на странице входа.

### 2. Плагины из маркетплейса (только установка и настройка)
| Плагин | Тип | Зачем в Sagas |
|---|---|---|
| `@directus-labs/dark-terminal-theme` | theme | Оформление панели |
| `@directus-labs/card-select-interfaces` | interface | Видимость сниппета — карточки Public / Unlisted с описаниями |
| `@directus-labs/spreadsheet-layout` | layout | Справочник языков редактируется как таблица |
| `@directus-labs/command-palette-module` | module | Палитра команд `Ctrl+K`: поиск по сниппетам и пользователям |

Плюс встроенный модуль Insights: дашборд «Sagas overview» (метрики, диаграммы
по видимости и языкам, последние сниппеты).

Плагины ставятся в Docker-образ (`cms/Dockerfile`), а все настройки применяет
скрипт `cms/setup.mjs`. Поэтому `docker compose up` на чистой машине даёт ту же
панель без ручных кликов.

### 3. Доработка руками — расширение `cms/extensions/sagas`
Бандл, собранный официальным `@directus/extensions-sdk`:

- **hook `sagas-guard`** (66 строк): переносит в CMS правила приложения.
  - Заголовок не длиннее 100 символов, без пробелов по краям, пустой → `Untitled`.
  - Код не пустой.
  - Язык существует в справочнике.
  - Приватную сагу нельзя изменить, удалить или создать: понятная ошибка
    `403 PRIVATE_SNIPPET` вместо «успешного» 204, который на самом деле ничего
    не менял (строку скрывает RLS в PostgreSQL), и вместо сырой SQL-ошибки 500.
- **display `code-preview`** (81 строка, Vue): в списке сниппетов показывает первую
  строку кода моноширинным шрифтом с номером строки и счётчиком «+N» вместо
  обрезанного текста.

Почему это нельзя сделать настройками: в бесплатной редакции Directus 12
кастомные правила валидации и прав запрещены, а встроенные displays не умеют
показывать код.

## Сравнение с лабами 6–8

| | Своё (лабы 6–8) | CMS (лабы 9–10) |
|---|---|---|
| **Что получили** | Публичный сайт: редактор, лента, просмотр, регистрация, «My sagas», API + Swagger | Админка: модерация сниппетов и пользователей, справочник языков, роли, дашборд, история изменений, комментарии |
| **Объём кода** | ≈650 строк Go + ≈1350 строк React/CSS + ≈125 строк SQL | ≈150 строк своего расширения + ≈540 строк `setup.mjs` (это декларативная конфигурация, а не логика) |
| **Скорость** | Каждую возможность пишем сами: форма, валидация, API, вёрстка | Таблицы, формы, фильтры, поиск, роли, дашборды, аудит — из коробки |
| **Гибкость UI** | Полная: дизайн из Figma, любая логика | В рамках админки Directus: темы, раскладки, интерфейсы полей. Нестандартное — только расширениями |
| **Бизнес-правила** | В Go-коде, в одном месте | Пришлось дублировать в hook. Это главная цена CMS: два входа в базу — две точки проверки |
| **Безопасность** | Свой код: bcrypt, сессии, CSRF, проверка владельца | Роли Directus + RLS и права на столбцы в PostgreSQL. Ограничения бесплатной редакции (нет прав на поля, нет правил-фильтров) пришлось закрывать на уровне БД |
| **Зависимость от вендора** | Нет | Версия Directus, лицензия, совместимость плагинов: 3 из 4 плагинов официально заявлены под v10–v11, работают, но без гарантий |
| **Для кого удобно** | Пользователи сайта | Не-программисты: модератор работает без кода и без деплоя |

**Вывод.** Публичную часть с нестандартным UX выгоднее писать самим: CMS
навязывает свой интерфейс. Административную часть — наоборот: то, на что
вручную ушли бы недели (CRUD-таблицы, фильтры, роли, аудит, дашборды), Directus
дал за вечер, а руками понадобилось дописать ~150 строк. Лучший результат дала
комбинация: свой фронт и API для пользователей и headless-CMS поверх той же
PostgreSQL для модерации.

## Вопросы темы (коротко)

**Отличия разработки на разных видах CMS.**
- **Монолитные** (WordPress, Drupal, Joomla): CMS сама рисует сайт. Работа — это
  выбор темы и плагинов, доработка на PHP через хуки и шаблоны темы.
- **Headless** (Directus, Strapi, Payload): CMS только хранит контент и отдаёт
  API, фронт пишется отдельно. Работа — модель данных, роли, расширения API и админки.
- **Database-first** (Directus): CMS строится поверх существующей БД — наш случай.
  **Code-first** (Strapi, Payload): схема описывается в коде CMS, и она создаёт таблицы сама.
- **SaaS** (Contentful, Sanity): хостинг у вендора, расширения — через их SDK и
  вебхуки, к БД доступа нет.

**Разработка на основе CMS с ИИ.**
- В самих CMS: в Directus 12 есть встроенный AI Assistant (виден в правой
  панели), MCP-сервер (`mcp_enabled` в `/server/info`) и AI-операции во Flows
  (генерация и перевод текста, alt-тексты к картинкам, модерация изображений —
  плагины `@directus-labs/ai-*`).
- В разработке: ИИ-ассистент пишет конфигурацию и расширения по описанию. Так
  сделаны `setup.mjs` и расширение `sagas`. Но результат обязательно проверять:
  при настройке всплыли несовместимости, которых не было в документации
  (ограничения лицензии Directus 12, отказ от email на `.local`, лишнее поле
  `password_hash` в форме) — их нашли только тестами и скриншотами.
